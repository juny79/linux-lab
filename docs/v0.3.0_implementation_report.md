## 1. 구현 목표 및 범위 선정 근거

`v0.1.0` 종합계획서와 `v0.2.0` B2C·온프레미스 상세설계서를 바탕으로, **실제 동작하고 즉시 검증 가능한 MVP(Minimum Viable Product) 시스템**을 구현했습니다.

### MVP 범위 선정의 논리적 근거
1. **전 계층(Junior → C-Level) End-to-End 파이프라인 검증**: 특정 레벨 하나만 깊게 파기보다, 터미널 실습형(Junior/Mid/Senior)과 의사결정 시뮬레이터형(C-Level)의 **서로 다른 두 UX/엔진 구조**를 초기부터 통합 검증해야 향후 시나리오 대량 생산 시 아키텍처 변경 비용을 최소화할 수 있습니다.
2. **B2C 구독 티어 접근 제어의 조기 내재화**: `Free / Pro / Executive` 티어별 권한 검증 로직을 세션 생성 API(`POST /api/sessions`) 계층에 선제적으로 구현하여, 비즈니스 모델과 인프라 리소스 할당이 강하게 결합되도록 설계했습니다.
3. **온프레미스 배포와 로컬 개발의 분리(Adapter Pattern)**: 실제 운영은 온프레미스 리눅스 베어메탈(KVM + Firecracker)에서 동작하지만, 개발/테스트는 Windows/macOS 로컬 환경에서도 즉시 가능해야 생산성이 극대화됩니다.

## 2. 아키텍처 및 기술 선택의 논리적 근거

### 2.1 Zero-Dependency Python 3.13 백엔드 채택
- **근거**: 온프레미스 폐쇄망/격리 환경 및 다양한 개발자 로컬 환경에서 외부 패키지(`pip`) 의존성 충돌 없이 즉시 구동·테스트할 수 있도록 Python 3.13 표준 라이브러리(`http.server.ThreadingHTTPServer`, `sqlite3`, `json`, `unittest`)만으로 코어 서버를 구현했습니다.
- **확장성**: 추후 트래픽 증가 시 `server.py`의 라우팅 계층만 FastAPI/Go로 교체하고, 핵심 도메인 로직(`provisioner.py`, `evaluator.py`)은 그대로 재사용할 수 있도록 계층을 분리했습니다.

### 2.2 Lab Provisioner 추상화 계층 (`backend/provisioner.py`)
- **`BaseProvisioner` 인터페이스**: `allocate()`, `execute_command()`, `destroy()` 3개의 표준 메서드로 실습 환경 생명주기를 추상화했습니다.
- **`OnPremFirecrackerProvisioner`**: 온프레미스 KVM 호스트에서 `infra/onprem/firecracker-launcher.sh`를 호출해 Copy-on-Write(`cp --reflink=auto`) 기반 MicroVM을 1초 내외로 스폰·파기합니다.
- **`LocalSimShellProvisioner`**: KVM이 없는 로컬 개발 환경에서도 4개 레벨 시나리오의 리눅스 명령어(`df`, `du`, `truncate`, `systemctl`, `sed`, `dmesg`, `ps`, `kill` 등)와 실시간 메트릭 변동을 완벽히 시뮬레이션합니다.

### 2.3 Scenario-as-Code 구조 (`scenarios/*.json`)
- **근거**: JSON은 YAML 1.2의 엄격한 부분집합(Strict Subset)이므로 외부 파서 없이 표준 라이브러리로 즉시 파싱 가능하며, GitOps 기반의 시나리오 버전 관리 및 PR 리뷰에 최적화되어 있습니다.
- 각 시나리오는 티켓 정보, 가상 Slack 알람, 토폴로지 스펙, 초기 장애 상태, 힌트, 포스트모템 평가 키워드를 선언적으로 정의합니다.

### 2.4 다차원 자동 채점 엔진 (`backend/evaluator.py`)
단순 정답/오답을 넘어 실무 역량을 정량화하기 위해 100점 만점을 3개 차원으로 배분했습니다.
- **시스템 상태 검증 (60점)**: 장애가 실제로 복구되었는지(파일 정리, 서비스 기동, 설정 변경, cgroup 제한 적용) 검증
- **과정 효율성 및 MTTR (20점)**: 불필요한 시행착오 없이 핵심 진단 명령어로 복구했는지 명령어 수와 복구 시간(MTTR) 측정
- **포스트모템 품질 (20점)**: 근본 원인 분석 및 재발 방지 키워드 반영 여부 평가 및 AI 리뷰 피드백 생성

## 3. 구현된 시스템 구조

```text
linux-lab/
├── backend/
│   ├── server.py               # HTTP API, B2C 티어 권한 제어, SQLite 영속화, 정적 UI 서빙
│   ├── provisioner.py          # Lab Provisioner 추상화 (OnPrem Firecracker / Local Sim Shell)
│   └── evaluator.py            # 다차원 자동 채점 엔진 & AI 동료 힌트 엔진
├── frontend/
│   └── index.html              # 통합 워크스페이스 UI (카탈로그, 가상 Slack/Jira, 웹 터미널, C레벨 보드)
├── scenarios/
│   ├── j01-disk-full.json      # [Junior] 디스크 100% 고갈 DB 장애 복구
│   ├── m01-haproxy-failover.json # [Mid-level] HAProxy 503 헬스체크 장애 복구
│   ├── s01-oom-killer.json     # [Senior] OOM Killer 분석 및 cgroup 메모리 격리
│   └── c01-region-dr.json      # [C-Level] 대규모 리전 장애 DR 의사결정 시뮬레이터
├── infra/onprem/
│   ├── firecracker-launcher.sh # 온프레미스 KVM + Firecracker MicroVM 프로비저닝 스크립트
│   ├── network-isolation.sh    # VLAN 30 Sandbox Egress 차단 및 로컬 미러 허용 nftables 규칙
│   └── docker-compose.yml      # Control Plane 배포용 Compose
├── tests/
│   └── test_platform.py        # End-to-End 자동화 테스트 스위트
└── docs/
    ├── CHANGELOG.md
    ├── v0.1.0_master_plan.md
    ├── v0.2.0_b2c_onprem_architecture.md
    └── v0.3.0_implementation_report.md
```

## 5. 다음 버전(`v0.4.0`) 고도화 계획
1. **실시간 WebSocket 터미널(`xterm.js`) 연동**: 현재 REST 기반 명령어 실행을 양방향 PTY + WebSocket으로 업그레이드하여 `vim`, `top`, `htop` 등 인터랙티브 TUI 명령어 완벽 지원
2. **LLM API 연동**: 현재 규칙 기반 AI 동료 힌트 및 포스트모템 리뷰를 실제 Gemini API와 연동하여 자유 형식 질문 대응 및 심층 코드/명령어 리뷰 제공
3. **온프레미스 Warm Pool 데몬**: 사전 부팅된 Firecracker MicroVM 풀을 유지하여 동시 접속자 급증 시에도 프로비저닝 대기 시간 1초 이내 보장
